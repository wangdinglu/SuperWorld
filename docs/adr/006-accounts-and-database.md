# ADR-006: Accounts and database

**Status:** Accepted · 3 Oct 2026

**Context.** Phase 2 needs saved accounts and places with revision history (M2.1). The project runs on free tiers, and contributors should be able to run everything with no setup.

**Decision.**

- **Postgres through Drizzle ORM** (`packages/db`), with SQL migrations generated by drizzle-kit and applied at startup.
- **Embedded Postgres (PGlite)** when `DATABASE_URL` is absent: tests run in memory, local development stores data in `.data/db`. Production should set `DATABASE_URL` (Neon's free tier is the suggested host).
- **Accounts start as guests** (a row per player, created on first visit and remembered on the device). A guest becomes a member by opening an emailed one-time link (hashed, 30 minutes). Signing in on another device with the same email returns the same account and moves any spaces the device's guest made.
- **Sign-in links always point at `PUBLIC_URL`** (or the server itself), never at an address in the request, so a link can't be redirected to another site.
- **Places and revisions:** revisions are immutable rows with the JSON Patch that produced them; a place's `published_revision` is what visitors see. Team-built places are seeded from `content/` on startup.
- Only `apps/server` may import `packages/db` (dependency-cruiser rule).

**Consequences.** No database setup for development or CI. On Render's free tier without `DATABASE_URL`, accounts reset on restart, which the server logs as a warning. Email is optional: without `RESEND_API_KEY`, links go to the server log.
